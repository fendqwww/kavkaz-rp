## Правила основателя (железные)
- секреты, пароли, ключи, токены — не в чат и не в git; ничего не удалять без подтверждения;
- платные и чужие модели в git НЕ кладём (репозиторий публичный): `resources/[cars]` и `resources/[maps]` в `.gitignore`, на VPS идут через tar/scp;
- коммиты на русском, повелительное наклонение, пуш в `claude/serene-franklin-9x1dw5`; перед коммитом `git diff --cached` на `cfxk_`, `mysql://`, `password`;
- чужие ресурсы не правим, а кладём копию в `overrides/resources/...` и помечаем изменения `-- KAVKAZ:`;
- пока карта не доделана, ничего другого не добавляем; без национальной темы, ориентир Majestic: минимализм;
- проверка только через лаунчер на VPS 13.141.51.196 (локальный сервер не считается), без всплывающих окон на ПК основателя;
- у основателя слабый ПК (FX-6300, RX 560 2 ГБ) и ~5 Мбит интернета: большие файлы только на VPS, по ssh.

## Как выкладывать
1. коммит и `git push origin claude/serene-franklin-9x1dw5`;
2. на VPS: `ssh root@13.141.51.196 "bash /root/deploy-vps.sh"` (копирует `overrides/resources` в базу ресурсов и `overrides/kavkaz.cfg`; делает бэкап в `/opt/kavkaz/backup-overrides/<дата>`);
3. машины и карты (`[cars]`, `[maps]`) — отдельно tar по ssh; сверять md5 или размеры, докачивать только недостающее;
   распаковывать `tar --no-same-owner -xf -` (или потом `chown fivem:fivem`): иначе файлы остаются с uid из Windows,
   сервер (пользователь fivem) не может сделать hard link в `cache/files/...` и клиент не скачает файл;
4. `systemctl restart kavkaz` — на сервере могут играть, перед рестартом спросить основателя;
5. лог: `/opt/kavkaz/txData/default/logs/fxserver.log` (ищи `SCRIPT ERROR`), `server.log` (входы и вылеты).
